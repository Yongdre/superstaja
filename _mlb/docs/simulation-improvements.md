# 2026-09-18 시뮬레이션 개선

2026-09-27 최종 점검 완료: KBO 118개·MLB 54개 테스트, 양쪽 TypeScript 검사와 배포 빌드가 통과했습니다. KBO 조정판 정규시즌 720경기와 MLB 정규시즌 2,430경기를 추가 실행해 득점·타석·투수 상대 타자 수의 일치를 확인했습니다. MLB 테스트에는 두 시즌 연속 진행과 은퇴까지 포함됩니다.

KBO/MLB에 같은 타격·주루·투수 개선을 적용했습니다. 기존 JSON 입력 항목은 그대로이고 선수 데이터 파일을 다시 만들 필요가 없습니다.

## 경기 처리

- 선발의 최소 이닝은 회차/초말이 아닌 실제 잡은 아웃 수로 판정합니다. 과투구·대량 실점은 최소 이닝 이전에도 조기 강판합니다.
- 끝내기 홈런이 아닌 타격은 승리 득점 이후 점수·타점을 추가하지 않습니다. 끝내기 장타의 공식 기록도 승리 주자의 진루 거리에 맞춥니다. 끝내기 홈런은 모든 주자와 타자의 득점을 인정합니다.
- 주자에 책임투수를, 경기에는 교체된 투수의 기록과 등판 당시 리드/주자 조건을 보관합니다. 승계주자의 실점·패전은 출루시킨 투수에게 귀속합니다.
- 세이브는 종료 점수 차가 아닌 등판 조건·리드 유지·투구 아웃 수로 판단합니다. 3점 차 주자 없는 2아웃 등판 후 아웃 하나는 세이브가 아닙니다. 동점 주자가 타석/대기타석에 있는 경우와 3이닝 이상 구원도 판정합니다.
- 5이닝 미달 선발 대신 구원투수에게 승리를 배정합니다. '가장 효과적인 구원'이라는 기록원 재량은 실점/아웃 수, 투구 아웃 수 순으로 근사합니다. 아주 짧고 부진한 구원에 대한 모든 재량 판정을 재현하지는 않습니다.

## 투수 운용

- 접전 후반은 구위·무브먼트·제구가 좋은 불펜을 우선합니다. 큰 점수 차에서는 좋은 불펜을 아낍니다.
- 9회 1~3점 리드의 이닝 시작에는 휴식 상태인 마무리를 우선 투입합니다. 마무리가 지쳤거나 이미 등판했다면 다른 투수를 사용합니다.
- 투구 수에 따라 실제 타석 판정에 쓰는 구위·무브먼트·제구가 완만하게 낮아집니다. JSON 원본과 화면의 기본 등급은 바꾸지 않습니다.
- 경기 간 피로는 투구 수 × 0.8을 누적하고 하루에 14씩 회복합니다. 불펜 기용 우선순위와 능력치에 반영됩니다. 같은 날짜 더블헤더에는 중간 회복이 없습니다. 선수별 생리학을 재현한 모델은 아니며 튜닝 가능한 단순 게임 모델입니다.
- MLB 정규시즌은 일정의 날짜, KBO는 경기일 번호를 사용합니다. 순차 진행하는 포스트시즌은 가상 경기일 기준이어서 실제 이동일/휴식 일정과 같지 않습니다.
- 투구 수는 BB 4~7구, SO 3~7구, 그 외 1~5구, 자동 IBB 0구로 추정합니다. 투구 단위 카운트 시뮬레이션은 아닙니다.
- 불펜을 모두 쓰면 마지막 투수가 피로를 적용받으면서 계속 던집니다. 재등판은 허용하지 않습니다.

## 주루

- 2아웃에서도 CPU 도루를 허용합니다. 도루 실패 아웃도 해당 투수의 투구 아웃 수에 포함됩니다.
- speed 7~10의 성공률/최대 시도 수는 기존 72%/30, 78%/40, 84%/50, 90%/60을 유지합니다.
- speed 1~6도 낮은 빈도로 시도합니다. 각각 성공률 45/48/52/57/62/67%, 최대 시도 1/2/4/7/12/20회입니다. 최대치까지 시도를 강제하지 않습니다.
- 도루 성공률은 투수/포수나 이전 성공·실패에 영향을 받지 않는 독립시행입니다. 사용자 지정 확률은 그대로입니다.
- 무사 병살 시 3루 주자는 득점 가능하고 타점은 주지 않으며 2루 주자는 3루로 갑니다. 1사 병살로 이닝이 끝나면 득점·진루하지 않습니다. 기본 6-4-3 병살 모델에 적용한 단순화입니다.

## 그대로 유지한 것

사용자의 타석 결과 직접 선택, 시즌 JSON 교체, 포스트시즌 4선발 순환, 저장 3슬롯을 유지합니다. KBO는 정규 12회/포스트시즌 15회 제한, MLB는 자동주자 없는 무제한 연장입니다.

## 저장 호환성

새 메타데이터는 선택 필드여서 기존 저장을 불러올 수 있습니다. 과거 확정 경기의 기록은 소급 변경하지 않습니다. 오래된 진행 중 세이브에 책임투수 정보가 없으면 현재 투수로 보완하며, 이미 교체된 투수/등판 조건을 정확하게 복원할 수 없으면 세이브를 임의로 만들어 부여하지 않습니다. 새 경기부터 완전한 추적이 적용됩니다. 피로 정보가 없는 기존 세이브는 누적 피로 0부터 시작합니다.

## 시즌 검증 도구

각 프로젝트 폴더에서 실행합니다. 사용자 선수를 제외한 원래 팀 라인업으로 정규시즌 전체를 반복 실행하며 파일·세이브를 변경하지 않습니다.

```powershell
pnpm audit:season --seasons=3 --seed=2026
node scripts/audit-season.mjs --seasons=10 --data=src/data/seasons/2017-season-data.json
```

두 번째 예시의 JSON 경로는 KBO용입니다. MLB는 해당 MLB JSON 경로로 바꾸세요. 출력은 평균 타율, 홈런, 득점/팀 경기, 볼넷·삼진/타석, 투구 수/타석, 선발 평균 이닝, 도루/실패, 팀별 성적과 입력 프로필 대비 기대 타율·홈런입니다. 득점 합계 및 타석 분해식, 투수 상대 타자 수가 맞는지도 검사합니다.

원본 JSON은 자동 수정하지 않으며 목표 성적을 강제로 맞추지 않습니다. 3시즌 결과만으로 선수별 ERA나 모든 팀 순위를 정밀 보정했다고 보지는 않습니다. 여러 seed로 결과를 비교한 뒤 입력 데이터와 엔진의 어느 쪽을 조정할지 판단하는 용도입니다.

KBO의 기존 `scripts/audit-simulation.mjs` 개별 타석 진단은 유지했고, `audit-team-balance.mjs`도 새 정규시즌 실행 경로를 사용해 경기 간 피로가 빠지지 않도록 했습니다.
