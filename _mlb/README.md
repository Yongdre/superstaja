# 슈퍼스타자 · MLB Edition

KBO 프로젝트와 별도로 실행하는 MLB 텍스트 타격 커리어 게임입니다. 이 폴더만 복사해도 개발·빌드할 수 있습니다.

## 실행

최근 엔진 개선과 저장 호환성·시즌 검증 방법은 [시뮬레이션 개선 안내](docs/simulation-improvements.md)를 참고하세요.

Node.js 24 이상과 pnpm을 사용합니다.

```powershell
cd "C:\Users\OWNER\Documents\ChatGPT\batting simulation\_mlb"
pnpm install --frozen-lockfile
pnpm dev
```

접속 주소는 http://localhost:5174 입니다. 기존 KBO의 기본 포트 5173과 분리했습니다.

```powershell
pnpm test
pnpm build
```

Cloudflare에는 **이 폴더 안의 `dist` 내용**을 별도 사이트로 업로드하세요. 상대 경로 빌드를 사용합니다. 실행 중 서버/API 키나 MLB API 연결은 필요하지 않습니다.

## 포함된 내용

- 실제 30개 구단과 AL/NL 각 3개 지구. 새 시즌에서 소속 구단을 선택합니다.
- 2026 MLB 공식 대진 횟수 기반 가상 일정: 전체 2,430경기, 팀당 162경기, 홈/원정 각각 81경기. 상대 구분은 지구 52경기, 같은 리그 타 지구 62경기, 인터리그 48경기입니다. 기존 연전을 끊지 않는 일정 묶음을 개막·최종 구간까지 포함해 무작위로 재배치합니다.
- 휴식일에는 타 구장 경기가 자동 진행됩니다. 더블헤더는 사용자 경기도 한 경기씩 진행하며, 중복 집계를 방지합니다.
- 각 리그 지구 우승 3팀 + 와일드카드 3팀. 1·2시드는 부전승, 3/6과 4/5 대결 후 고정 경로로 진출합니다. KBO의 4위 1승 어드밴티지는 없습니다.
- WC 3전 2선승(상위 시드 홈), DS 5전 3선승(2-2-1), CS/WS 7전 4선승(2-3-2). CS는 상위 시드, WS는 정규시즌 성적과 해당 두 팀의 동률 기준으로 홈 이점을 정합니다.
- 대진표 메뉴: SVG 토너먼트 연결선, 시드·승수·승자·현재 시리즈·우승팀. 시즌 중에는 예상 대진이고 시즌 종료 시 확정됩니다. 포스트시즌 경기 결과 화면에도 표시합니다. 모바일은 가로 스크롤로 확인합니다.
- 정규시즌·포스트시즌 모두 자동주자 없이 연장을 진행합니다. 12회 등 이닝 제한이나 무승부 없이 승부가 날 때까지 진행하는 사용자 지정 규칙입니다.
- 포스트시즌 1~4선발을 팀별 누적 경기 순서로 운용하고 5선발은 불펜으로 전환합니다. 동일 경기 재등판을 방지합니다.
- 기존 타격 선택·기록·시리즈 기록·커리어·시즌별 JSON 교체·시즌별 도루 성공률·은퇴·수동 저장 3슬롯을 유지합니다.
- 실제 끝내기 결과와 팀 승리를 순서대로 표시합니다. 기존 타점·득점·홈런·사이클링 히트 알림과 함께 재생됩니다.
- 정규시즌 50안타·10홈런·10도루마다, 통산 1,000안타·100홈런마다 달성 알림을 2초씩 표시합니다. 통산 달성 이력은 경기 날짜·차전·이닝·상대 팀과 함께 기록 화면과 세이브에 보존합니다. 이전 세이브에서 이미 지난 기준의 달성 시점은 복원하지 않습니다.

## 선수 데이터와 일정의 범위

**기본 데이터는 2016년 실제 MLB 선수·공식 기록을 바탕으로 만든 압축판입니다.** 30팀마다 타자 9명, 투수 11명(5 SP / 5 RP / 1 CP), 총 600명을 배치했습니다. 백업과 나머지 투수들의 기록을 대표 선수의 성적·능력치에 반영했으므로 JSON 수치는 실제 개인 기록 그대로가 아니라 게임용 추정치입니다. 타자는 모두 162경기 출장 설정이며, 사용자가 선택한 포지션에는 기존 게임처럼 사용자 선수가 들어갑니다.

편집·가져오기할 파일: `src/data/seasons/mlb-league-data-2016.json`

새 커리어의 기본 데뷔 연도와 최신 입력 템플릿도 2016 압축판입니다. 기존 `mlb-league-data-2026.json`은 실제 선수가 아닌 가상 템플릿으로 남겨 두었습니다. 선정 기준·성적 합산·능력치 환산·제약은 [2016 데이터 설명](docs/2016-data-guide.md)에 있습니다.

타자는 기존 방식대로 `statProfile.games`(최대 162), `avg`, `homeRuns`, `eye`(1~10), `speed`(1~10)를 입력하고 `position`에는 `2B,3B,SS` 등 멀티 포지션을 쓸 수 있습니다. `bats`는 L(좌타), R(우타), S(양타)입니다. 사용자 선수를 제외한 구단 원본이 완전한 라인업을 만들 수 있도록 타자 출장 합계는 9×162=1,458 이상이어야 합니다. 투수는 `stuff`, `movement`, `control`, `stamina`(0~100), `role`, `grade`를 사용합니다. 화면 등급만 바꿔도 능력치가 바뀌지는 않습니다.

실행 중 새 커리어나 다음 시즌 설정에서 JSON을 가져오면 재빌드하지 않아도 됩니다. 이미 진행 중인 세이브는 당시의 선수 데이터를 포함하므로 기존 파일 편집/새로고침으로 소급 변경되지 않습니다.

JSON의 팀 key와 `id`는 `ATH`/`OAK`, `AZ`/`ARI`를 같은 팀으로 인식합니다. 기본 화면 약칭은 `OAK`, `ARI`로 변환하며 직접 작성한 한글 등의 `shortName`은 유지합니다. 일정·기존 세이브 호환을 위해 내부 및 내보낸 JSON의 팀 ID는 `ATH`, `AZ`를 유지하고 선수 ID는 바꾸지 않습니다. 동일 구단을 두 약칭으로 중복 작성하면 오류를 표시합니다.

일정 데이터는 `src/data/mlb-schedule-2026.json`, 리그/지구 구분은 `src/data/mlbTeams.json`입니다. 일정 API의 재편성·재개에 따른 중복 gamePk는 마지막 날짜 항목으로 합쳤습니다. 실제 경기 결과와 승패는 가져오지 않으며 게임에서 새로 시뮬레이션합니다. 날씨에 따른 추가 취소·서스펜디드 경기 재개는 재현하지 않습니다.

**모든 새 시즌은 2026 상대별 경기 수와 시즌 날짜 범위를 유지하되 일정 묶음 순서를 무작위로 바꾼 가상 일정**을 사용합니다. 연전 및 더블헤더의 원래 경기 순서는 유지하며 개막·최종 구간도 이동합니다. 실제 요일·이동 휴식 배치는 달라지므로 실제 그 연도의 공식 일정이라는 의미는 아닙니다. 새 커리어는 Seed를 자동 생성하고 같은 연도·Seed를 입력하면 일정을 재현합니다. 다음 시즌에는 다시 편성하며 진행 중인 세이브 일정은 유지합니다. 포스트시즌은 현행 대진/선승/홈 배분을 따르되, 실제 TV 편성 날짜·양 리그 동시 진행·이동 휴식일은 생략하고 시리즈 단위로 순차 진행합니다. 선발 4인 순환은 게임 운용 규칙이며 MLB가 강제하는 규정은 아닙니다.

동률은 상대전적(복수 팀이면 우세 팀/그룹 상대 승률), 지구 내 성적, 같은 리그 성적, 올스타전 이후 같은 리그 성적, 이전 경기 추가 순서로 비교합니다. 모든 데이터까지 같으면 결정적인 ID 순서로 구분합니다. 실제의 모든 예외적 다자 동률 판정을 완전히 재현하는 규칙 엔진은 아닙니다.

타석 결과 중심의 게임이므로 투구별 피치클록·ABS 챌린지·리플레이·실제 26인 로스터 운용은 모델링하지 않습니다. 사용자 선택 결과는 기존 게임처럼 그대로 반영됩니다.

## 저장 호환성

MLB 자동 저장 및 수동 슬롯 키는 `mlb-sim-*`이고 KBO의 `kbo-sim-*`와 다릅니다. 세이브에도 `edition: "MLB"`를 넣고 KBO 세이브는 거부합니다. 기기 간 진행을 옮기려면 MLB 세이브 JSON을 내보내서 다른 기기에서 가져오세요.
