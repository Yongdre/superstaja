# 2017 시즌 데이터 안내

게임에 가져올 파일은 **`2017-season-data.json` 하나**입니다.

## 현재 버전: 사용자 지정 팀 체급 조정판 (2026-09-09)

실제 기록 기반 초안에서 아래 전력 관계가 나타나도록 타자 입력 성적과 투수 능력치를 조정했습니다.

**KIA = 두산 >> 롯데 = NC >>> SK >> LG = 넥센 >>>> 한화 >>> 삼성 >>>> kt**

같은 단계는 비슷한 전력, 부등호는 단계 사이의 격차로 해석했습니다. 승수나 순위를 강제하는 기능은 넣지 않았습니다. 게임 엔진의 판정·확률식도 바꾸지 않았습니다.

| --- | --- | --- | --- | --- | --- |

타율은 .170–.399, eye는 1–10, 투수 세 능력치는 15–99, 체력은 25–99로 제한하고 홈런은 반올림했습니다. 주루, 선수 명단, 수비 위치, 타순 배열, 보직은 유지했습니다.

하위 팀에도 핵심 투수가 남도록 삼성 윤성환(+8)·백정현(+4), kt 피어밴드(+14)·고영표(+9)는 위 투수 가감값에 추가 보정을 적용했습니다. 예를 들어 삼성의 일괄 -13에도 윤성환은 최종 -5입니다. 등급은 변경된 세 능력치로 다시 계산했습니다. `strength`도 요청한 체급에 맞는 표시값으로 바꿨지만, 실제 효과는 타자·투수 입력값에서 발생합니다.

원본은 `docs/sources/2017-season-data-before-balance.json`, 조정 설정은 `scripts/data/2017-team-balance.json`에 보존했습니다. 후반의 **조정 전** 성적·능력치 설명은 이 백업을 기준으로 한 것이며, 현재 게임 파일은 위 가감값까지 적용한 버전입니다.

## 적용 방법

1. 메인 화면에서 **새 시즌 시작**을 열고, **수정한 JSON 가져오기**로 `2017-season-data.json`을 선택합니다.
2. 리그 데이터 이름이 **2017 KBO 팀 체급 조정판**으로 바뀌었는지 확인합니다.
3. 선수 설정을 마치고 시작합니다. 다음 시즌 설정에서도 **JSON 가져오기**로 선택할 수 있습니다.

이것은 **리그 데이터**이며, 경기 진행 상황을 담는 **세이브 JSON**과 다릅니다. `JSON 세이브 불러오기`에 넣지 마세요.

요청하신 파일 이름을 그대로 사용했습니다. 현재 앱은 `kbo-league-data-YYYY.json`이라는 이름만 자동 내장하므로, 이 파일은 폴더에 두거나 빌드하는 것만으로 기본 데이터가 바뀌지 않습니다. 위 메뉴로 직접 가져오면 됩니다. Cloudflare에 올린 기존 사이트에서도 파일 가져오기를 사용할 수 있으며, **이 JSON을 수정해서 가져오는 데에는 재빌드가 필요 없습니다.** 기존 내장 파일이나 저장된 커리어는 덮어쓰지 않았습니다.

이미 진행 중인 시즌은 세이브에 이전 데이터가 포함되어 있으므로 새로고침만으로 바뀌지 않습니다. 새 커리어나 다음 시즌 설정에서 가져오세요.

## 실제 기록의 출처

[KBO 공식 자료실](https://www.koreabaseball.com/Kbo/Board/Ebook/EbookYear.aspx)의 **[2018 KBO 연감](https://6ptotvmi5753.edge.naverncp.com/KBO_FILE/ebook/pdf/2018_%EC%97%B0%EA%B0%90.pdf)**에 수록된 **2017 정규시즌** 기록을 사용했습니다. 2018 선수 성적을 사용한 것이 아닙니다.

- 인쇄 쪽수 255: 리그 전체 기록.
- 259–278: 팀별 투수·타자 기록 대조.
- 443–493: 투수 연도별 성적 중 `17`년 행, 투구 손.
- 494–552: 타자 연도별 성적 중 `17`년 행, 타격 손.
- 확인일: 2026-09-08. 연감 발행 시점의 기록이므로 이후 공식 정정은 반영하지 않을 수 있습니다.

190명의 환산 전 기록과 선수별 출처 쪽수는 `docs/sources/2017-kbo-records.json`에 따로 보관했습니다. 이 자료 파일은 게임에 가져오는 파일이 아닙니다. 이닝은 소수 표기의 혼동을 막기 위해 아웃 수(`inningsOuts`)로 저장했습니다. 예: 양현종 193⅓이닝 = 580아웃.

## 명단을 줄인 방식

- 10개 팀 × 타자 9명 + 투수 10명 = **190명**. 가상 백업 선수는 없습니다.
- 타자 9명은 C, 1B, 2B, 3B, SS, LF, CF, RF, DH를 하나씩 담당합니다. 모두 `games: 144`, `availability: REGULAR`입니다. 사용자 선수는 선택한 수비 위치의 기존 선수를 대신합니다.
- 실제 부상·휴식·시즌 도중 합류 일정은 재현하지 않습니다. 예를 들어 94경기 출장한 김태균도 이 판에서는 144경기를 뛰는 설정입니다.
- 투수는 **SP 5명, RP 4명, CP 1명**입니다. SP 배열 순서가 1–5선발이며, 기존 포스트시즌 규칙에 따라 5선발은 불펜으로 이동합니다.
- 정규시즌 중 보직을 바꾼 선수도 역할 하나로 고정했습니다. 예: 함덕주·백정현·한현희는 SP, 조정훈·조상우는 RP. 김세현(KIA), 박정배(SK), 신정락(LG)을 각 팀의 단일 CP로 지정했습니다. 당시 모든 보직 변동을 재현한 명단은 아닙니다.
- 이적 선수는 **2017 정규시즌 전체 합산 성적**을 사용하되 최종 소속 한 곳에만 배치했습니다. 예: 이명기·김민식·김세현→KIA, 노수광→SK, 윤석민·오태곤→KT, 최재훈→한화, 장시환→롯데, 김성민→넥센.
- 강민호는 롯데, 민병헌은 두산입니다. 2018년 이적을 미리 적용하지 않았고, 2017년 1군 출전이 없는 김광현은 제외했습니다.
- 로하스는 실제 양타지만 현재 게임의 `bats`가 L/R만 지원해 L로 표기했습니다. 원자료에는 S로 남겼습니다.
- 수비 위치, 보직, 선발 순서는 플레이용 편집입니다. 9명 제한 때문에 일부 주요 선수도 빠져 있습니다.

## 조정 전 타자 입력값 (백업 기준)

게임 JSON의 `statProfile`에는 기존에 정한 다섯 항목만 넣었습니다.

| 항목 | 이번 파일의 입력 기준 |
| --- | --- |
| `games` | 모두 144 |
| `avg` | 실제 2017 타율 유지 |
| `homeRuns` | `반올림(실제 HR × min(144 / 실제 G, 2))` |
| `eye` | `반올림((실제 BB / 실제 PA - 0.048) / 0.008)`, 1–10 제한 |
| `speed` | 아래 도루 시도량 기준으로 1–10 등급화 |

홈런은 예를 들어 안치홍 132경기 21홈런→144경기 **23홈런**, 최정 130경기 46홈런→**51홈런**입니다. 초이스는 46경기 17홈런을 단순 환산하면 약 53개라서, 짧은 표본의 과대평가를 줄이는 **최대 2배 규칙**에 따라 **34홈런**으로 입력했습니다. 이 상한은 게임용 판단이며 공식 예측치가 아닙니다.

선구안은 사구를 빼고 **볼넷 / 타석**으로 계산했습니다. 현재 엔진의 `eye`별 기본 볼넷 확률과 맞춘 것으로, 실제 볼넷률을 정확히 재현하지는 않습니다. 예를 들어 최형우는 상한인 10이며, 그의 실제 볼넷률은 게임의 `eye: 10` 기본 확률보다 높습니다.

주루는 `환산 도루 시도 = (SB + CS) × min(144 / G, 2)`를 사용합니다. 실측 주력은 아니며 시도량의 대략적인 대용값입니다.

| 환산 시도 수 이상 | speed |
| --- | --- |
| 48 | 10 |
| 35 | 9 |
| 25 | 8 |
| 14 | 7 |
| 9 | 6 |
| 5 | 5 |
| 2 | 4 |
| 1 | 3 |
| 1 미만 | 2 |

현재 자동 도루는 speed 7–10에만 있으며, 각각 **72%·30회 / 78%·40회 / 84%·50회 / 90%·60회**의 성공 확률·시즌 시도 상한을 사용합니다. 투수 능력치에 따른 추가 보정은 없습니다. **실제 2017 성공률을 그대로 넣은 것은 아니며**, 출루와 경기 상황에 따라 상한보다 적게 시도할 수 있습니다. speed 6 이하 선수의 소수 도루는 현재 엔진에서 자동 재현되지 않습니다.

## 조정 전 투수 능력치와 등급 (백업 기준)

방어율은 능력치 산정에만 참고하고, 게임 파일에는 **stuff / movement / control / stamina / grade**를 넣었습니다. `statProfile`은 넣지 않아 가져오기 중 기존 자동 변환식이 능력치를 다시 덮어쓰지 않습니다.

2017 연감의 리그 전체 아웃 수·자책점·삼진·볼넷·피홈런으로 평균 ERA, K/9, BB/9, HR/9를 계산했습니다. 기준 능력치는 현재 엔진의 중립점인 **72**입니다. 이는 보편적인 야구 선수 평가 기준이 아니라 **이 게임을 위한 초안**입니다.

```
IP = 실제 아웃 수 / 3
신뢰도 = IP / (IP + 30)       # SP
신뢰도 = IP / (IP + 15)       # RP, CP
성적차 = (리그 ERA - 선수 ERA) × 7

stuff    = 72 + 신뢰도 × (성적차 + (선수 K/9 - 리그 K/9) × 4.5)
movement = 72 + 신뢰도 × (성적차 + (리그 HR/9 - 선수 HR/9) × 7)
control  = 72 + 신뢰도 × ((리그 BB/9 - 선수 BB/9) × 8 + 성적차 × 0.2)
```

세 능력치는 반올림 후 30–97로 제한합니다. 짧은 이닝의 좋은/나쁜 기록은 중립 쪽으로 조금 줄였습니다. 실제 구속·회전·구종 움직임을 조사해서 수치화한 것은 아니고, 기록을 활용한 추정입니다. 구장 효과와 수비 지원까지 분리하지 않았습니다.

체력은 이번 버전에서 시즌 투구량과 고정 보직으로 근사했습니다.

- SP: `38 + IP × 0.28`, 60–96 제한.
- RP: `35 + IP / 5`, 38–55 제한.
- CP: `30 + IP / 5`, 35–45 제한.

따라서 늦게 합류하거나 부상으로 적게 던진 선발의 체력이 낮아질 수 있습니다. 실제 선발 등판당 투구 수를 이용한 정밀 체력 평가는 아닙니다.

등급은 **구위·무브먼트·제구의 산술평균**으로 계산하며 체력은 제외합니다. S≥85, A≥78, B≥70, C≥60, 그 미만 D입니다. 표시 등급이 확률에 별도 보너스를 더하지 않습니다.

| 투수 | stuff | movement | control | stamina | grade |
| --- | --- | --- | --- | --- | --- |
| 양현종 | 82 | 83 | 81 | 92 | A |
| 헥터 | 80 | 82 | 82 | 94 | A |
| 허프 | 87 | 90 | 89 | 73 | S |
| 손승락 | 95 | 88 | 85 | 42 | S |

수치를 직접 바꾸면 `grade`도 같은 기준으로 함께 바꾸거나, `grade` 필드를 삭제해 게임이 자동 계산하도록 할 수 있습니다.

## 어느 정도의 재현인가요?

**실제 기록 기반의 간소화된 주전에 사용자가 요청한 팀 체급을 반영한 시즌**이지, 2017년 승패·순위를 그대로 재현하는 데이터는 아닙니다. 백업·부상 일정 생략, 출전 확대, 투수 보직 고정, 엔진의 확률 처리 때문에 타율·홈런·방어율·팀 승수는 달라집니다. 현재 엔진은 `strength` 숫자로 승률을 강제하지 않습니다.

최초 실제 기록 환산 로직은 `scripts/generate-2017-season-data.mjs`, 현재 체급 조정판 생성은 `scripts/generate-balanced-2017.mjs`에 남겼습니다. 두 스크립트 모두 Node 24에서 JSON을 화면에 출력할 뿐 파일을 자동으로 덮어쓰지 않습니다. 평소에는 게임용 JSON만 편집하면 됩니다.
